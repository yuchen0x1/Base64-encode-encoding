# 安装更新后没有重新打开：故障复盘

## 实际证据

2026-11-13 用户反馈：旧版本已安装，下载安装包后点击安装 / 重启，应用退出后没有反应。

只读检查显示，实际安装仍为 **0.0.4**；14:15 与 14:19 两次尝试产生了更新助手 EXE，但安装日志没有新增助手启动记录。更新目录的 Chromium 日志记录：

```text
Invalid file descriptor to ICU data received.
```

因此这两次故障发生在安装助手的原生运行时启动阶段，尚未执行安装脚本。没有把早先 04:57 的安装失败日志当作本次证据，也没有由安装器退出码推断本次安装成功。

## 根因与复现

0.0.4 / 0.0.5 为避免安装助手占用应用目录，把 Electron EXE 单独复制到更新目录，但漏掉了它启动所需的数据文件：

- `icudtl.dat`；
- `snapshot_blob.bin`；
- `v8_context_snapshot.bin`。

在当前项目的独立临时目录，用现有安装的运行文件复制复现：

| 内容 | 结果 |
|---|---|
| 只复制 EXE | 退出码 2147483651，ICU 错误，Node 代码未执行 |
| EXE + ICU 数据 | 同样退出，报 V8 startup snapshot 加载失败 |
| EXE + ICU + 两份 V8 启动数据 | 退出码 0，成功执行 Node 探针 |

之前的单测和隐藏渲染器检查没有覆盖“复制到应用目录外的助手运行时”这一真实边界，因此未拦住问题。新版不把“进程创建请求返回”当作助手已经就绪。

## 修复

- 独立运行目录复制完整的启动文件，并写入明确的 ES module 配置；缺失文件会在当前应用退出前失败。
- 助手验证安装参数后，通过专用 IPC 通道确认就绪；主进程收到匹配目标版本的确认，才允许退出。
- 启动失败、崩溃、错误版本或超时时，旧应用继续运行并返回错误。重复安装请求被拒绝。
- 助手的工作目录位于安装目录之外；新版本进程的工作目录明确设为安装目录，启动进程错误会被捕获。
- 临时文件的延迟清理使用 PowerShell 的 LiteralPath 和环境变量，不拼接用户路径到命令字符串。
- 发布工作流增加真实独立运行时检查，避免只检查渲染器或归档就发布。

## 验证与边界

`npm run test:updater` 使用已安装的 Electron 运行文件创建真实独立进程，执行实际助手模块并取得就绪确认；同时验证 EXE-only 失败不能交接、父进程仍运行。该检查不会执行安装器，也不会写入用户原有安装或配置。

单元测试覆盖完整文件复制、就绪确认、崩溃 / 超时、旧进程退出门禁和重复安装。安装器归档、目标版本与实际 GUI 启动分别验证，不能互相替代。

**升级恢复：已安装的 0.0.4 / 0.0.5 使用的是旧更新器，必须先手动覆盖安装修复版本一次。** 更新服务器上的新安装包无法让已经崩溃的旧助手执行代码。不需要卸载或清空用户数据。

用户明确授权后，使用本地构建并校验的 v0.0.6 安装包，覆盖升级原有 v0.0.4。安装前将用户配置备份到项目内被 Git 忽略的临时目录，未删除用户数据。
