# 批量处理与配方

所有运算在本地完成，没有新增服务端 API、数据库或生产依赖。输入与结果只保留在当前页面内存中，不写入工作区备份。导出结果是用户主动保存数据的操作。

## 使用流程

1. 搜索「批量」并打开「批量处理模式」，选择文本或文件输入。
2. 文本每行一条，文件每个一条。多行 JSON 请作为一个 `.json` 文件输入；文本模式按行拆分，不会自动合并多行 JSON。
3. 在「处理流程」中选择第一步，需要时添加后续步骤，使用上下箭头调整顺序。
4. 点击「开始处理」。运行期间输入与流程锁定；点击「停止」会终止当前后台运算 / 文件读取，保留之前完成的条目。
5. 按成功 / 失败或关键词筛选结果。每页最多 100 条；「复制全部」和导出始终针对本批全部已完成结果，不受分页和筛选影响。

内置常用配方：

| 配方 | 用途 |
|---|---|
| Base64 解码 → JSON 格式化 | 批量查看编码后的 JSON |
| JSON 压缩 → URL 编码 | 将 JSON 转成 URL 参数值 |
| Base64 解码 → SHA-256 | 计算编码前原始字节的摘要，包括非文本二进制 |

URL-Safe 控制所有 Base64 **编码**步骤的输出；解码同时接受标准与 URL-Safe 字母表。大写输出控制所有哈希步骤。跳过空行只影响文本输入的条目拆分。这些选项作用于整个流程。

## 数据与错误语义

步骤之间传递字节。`Base64 解码 → SHA-256` 直接哈希解码后的二进制，不会先替换乱码再哈希。Base64 编码和哈希可处理任意字节；URL、JSON 以及最终文本输出必须是有效 UTF-8。

单条失败会标出具体步骤并继续后续条目。文件不可读、文本损坏、非法 Base64 / URL / JSON 均显示错误，不用空白冒充成功。空文件的哈希或编码仍是有效结果。

JSON 步骤直接重排原始 JSON 标记，不把 JS Number 重新序列化，因此 64 位整数、高精度小数、指数形式及重复键会保留原文。美化最多支持 256 层嵌套以避免输出膨胀，压缩仍可处理更深嵌套。单独 JSON 工具的键排序 / 清理会拒绝会丢失数字精度或重复键的输入，不会静默改值。

停止时进度保持实际完成条目数。当前未完成条目不记录为失败；可导出此前完成的结果。修改流程后，结果栏仍保留原运行内容并显示提示，JSON 导出仍引用原配方。重新开始会生成一批新结果。

## 资源边界

| 边界 | 限制与行为 |
|---|---|
| 流程 | 1–8 步，只接受内置操作 |
| 批次 | 最多 1000 行或 1000 个文件 |
| 文本单行 | 2 MiB，超出则该条失败 |
| 单文件 | 64 MiB，读取前检查，超出则该条失败 |
| 整批输入 | 128 MiB，超出不开始，保留上次结果 |
| 单条中间结果 | 96 MiB，超出则该条失败 |
| 整批成功输出 | 128 MiB，超过则停止且保留已有结果 |
| 配方文件 | 16 KiB，读取前及解析前分别检查 |
| 单条后台处理 / 文件读取 | 15 秒，超时终止；后续条目可继续 |
| 结果展示 | 每页 100 条，展开预览最多 200000 字符；完整内容可复制 / 导出 |

界面以 MB / KB 简写显示二进制大小。限制是应用层保护，不代表所有设备均能以同样速度处理上限数据；大文件仍会占用相应内存。

## 配方文件

「导出配方」只保存版本化步骤及选项，不保存文件名、输入内容、结果或密钥。不会自动持久化或通过 URL 分享配方。

```json
{
  "kind": "geek-toolbox-batch-recipe",
  "version": 1,
  "steps": ["base64-decode", "json-format"],
  "options": {
    "urlSafeBase64": false,
    "upperHash": false,
    "skipEmpty": true
  }
}
```

支持的操作 ID：`base64-encode`、`base64-decode`、`url-encode`、`url-decode`、`md5`、`sha1`、`sha256`、`json-format`、`json-minify`。不执行脚本，不加载外部操作；未知操作、错误版本、非布尔选项和非法 JSON 都会被拒绝，原流程保留。导入时只保留白名单字段，额外内容不会进入再导出的配方。

## 结果文件

- TXT：逐条原始结果或错误，带来源标题。
- JSON：保留原 `operation`、`generatedAt`、`total`、`rows` 字段，附加 `recipe`、`startedAt`、`sourceMode`、`status`、`requestedTotal`；停止 / 中断时 `total` 是已完成数量，`requestedTotal` 是原请求数量。
- CSV：带 UTF-8 BOM，所有单元格正确引用和转义；对公式及控制字符前缀添加单引号，使首次打开时按文本处理。输出可能包含额外单引号，逐字保留数据请用 JSON / TXT。

CSV 被电子表格再次保存、再打开后的解释取决于该软件；初次导出的转义不保证经过外部软件改写后的安全性。依据：[OWASP CSV Injection](https://owasp.org/www-community/attacks/CSV_Injection)。

## 开发与验证

`batchProcessing.js` 提供配方校验、字节转换和导出逻辑；`batchWorker.js` 是后台入口；`batchRunner.js` 负责 Worker 复用、超时及终止。界面只负责输入、运行状态和结果展示。扩展操作时同步更新操作表、执行实现及测试，不使用动态代码或外部插件。

```sh
npm test
npm run lint
npm run build
npm run test:desktop
```

真实浏览器检查需要可用的 Python Playwright 和 Chromium，使用独立临时浏览器上下文，不读取日常浏览器资料。先启动生产构建服务，再运行：

```sh
node server/serve.js --port 4186
python tests/browser/batch_smoke.py --url http://127.0.0.1:4186
```

截图和检查摘要默认保存在忽略的 `.tmp-verify/browser/`。浏览器检查涵盖多步流程、下载文件内容、无效配方、字节哈希、分页、停止、响应式布局、二维码错误恢复和全部工具入口。Electron 检查在隐藏窗口中验证生产文件加载和沙箱内 Worker，不涉及安装包、更新安装、代码签名或发布。
