# v0.0.6 发布产物检查

## 1. 总览

2026-11-13，对本地 Windows 打包目录执行 Electron 静态扫描，评分仍为 59/D。此分数反映未签名与第三方二进制信息，不是安全认证；本项目为 MIT 开源工具箱，不以 ASAR 或压缩提供源码保密。本版是更新运行时故障修复，没有新增依赖、账号服务或数据迁移。

## 3. 证据与修复

- 扫描原始结果在忽略目录 `.tmp-verify/v006-exposure.json`。打包排除规则未放宽，实际 NSIS 内的 ASAR 包含 28 个应用条目及完整的更新助手模块。
- `Get-AuthenticodeSignature` 对本地安装包返回 NotSigned；发布清单未声明已经签名。
- 主进程必须收到助手目标版本一致的 IPC 就绪确认后才退出；真实复制出的 Electron 运行时、实际助手模块和故意缺文件的失败场景均已运行验证。
- 用户授权后实际覆盖升级 v0.0.4 → v0.0.6，确认窗口正常打开；此记录不等同于自动更新端到端验证。详细证据见 [故障复盘](../UPDATER_INCIDENT_2026-11-13.md)。

## 4. 客户端无法解决的问题

SHA-256 只验证文件一致性，不能单独认证发布者或清单。正式签名和可信更新清单仍需单独配置。公开客户端及其本地算法可被读取，本版不承诺阻止逆向。

## 5. 后续顺序

1. 配置正式 Windows 签名和清单认证。
2. 在后续真实版本间完成自动发现、下载、安装、启动以及失败恢复的整链路验收。
3. 专项改造更新助手后再收紧相关 Electron fuse，避免直接关闭 RunAsNode 导致更新再次失效。
