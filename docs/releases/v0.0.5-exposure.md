# v0.0.5 发布产物暴露面检查

## 1. 总览

2026-11-13，检查当前项目的网页构建、Windows NSIS 安装包及其 ASAR（Electron 应用归档）。这是 MIT 开源工具箱，源码可读是产品定位；本检查不尝试阻止合法研究，也不把压缩 / 无 source map 宣称为代码保密。

静态扫描网页产物无命中（脚本评分 100/A）；桌面初次扫描 33/D，排除多余依赖与 source map 后为 59/D。原始分数受第三方运行库、未签名和主 EXE 被大小限制跳过影响，仅用于比较，不是安全认证。主 EXE 的 fuse 另用已安装 `@electron/fuses` 读取。

## 3. 逐项证据与修复

- `package.json` 的打包白名单继续包含 dist / electron / shared / package.json，并显式排除 `node_modules/**/*` 与 `**/*.map`。桌面主进程和更新模块的导入全部为 Electron、Node 内置模块或本仓库相对文件；前端依赖已由 Vite 打包，不需要在桌面载荷附带这些依赖。
- 从最终安装包内的 `app-64.7z` 提取 `resources/app.asar`，确认 `package.json` 与 `dist/version.json` 均为 0.0.5，且无 node_modules 文件或 source map。不是只检查输出目录中的散文件。
- 隐藏 Electron 沙箱窗口直接加载最终 ASAR 内的 dist，Base64 解码 → 二进制 SHA-256 与原生摘要对照通过；不构成完整安装 / 更新验收。
- 发布脚本使用已有的 `electron-winstaller/vendor/7z-x64.exe` 完成 NSIS 外层和内层载荷 CRC 校验。首次因系统没有 7z 失败，指定 `TOOLBOX_7Z` 后正常通过；未使用 `--skip-verify`。
- 最终桌面 / 网页更新清单的版本、包大小和 SHA-256 与对应文件重新计算一致。签名检查返回 `NotSigned`，没有声明已签名。
- fuse wire 按枚举读取：RunAsNode=true、EnableNodeOptionsEnvironmentVariable=true、EnableNodeCliInspectArguments=true、EnableEmbeddedAsarIntegrityValidation=false、OnlyLoadAppFromAsar=false。更新助手依赖 `ELECTRON_RUN_AS_NODE`，直接关闭会破坏更新，未在发版阶段盲目切换。
- 原始扫描和对比位于忽略的 `.tmp-verify/release-exposure-*.json`。JS source map 项与依赖目录项在修复后消失；残留引用和第三方二进制条目已人工区分。

## 4. 客户端无法解决的问题

- ASAR 不是加密格式，公开客户端及其算法始终可被读取。本项目本来就公开源码，混淆不能提供密钥保护。
- 工具输入只做本地计算，本轮未发现新增业务账号、授权判定或长期服务密钥。打包产物不包含 `.env`、测试资料、审计临时目录或用户工作区备份。
- SHA-256 能检测下载损坏，不能单独认证更新清单及发布者。未签名分发仍依赖可信 GitHub Release / 自定义更新源。证书和清单认证需要独立配置、真实升级与回滚验收。
- 依赖漏洞数据库审计本次再次遇到官方 registry 的 ECONNRESET，未取得有效报告；不宣称零漏洞。

## 5. 修复顺序

1. P0：若后续发现真实凭据进入客户端，立即撤销并迁移至服务端；当前检查未发现这类新增凭据。
2. P1：本次已清除依赖 source map 和多余依赖，保留完整性检查。下一步配置正式 Windows 签名与发布者认证，并完成隔离环境下的真实安装 / 更新 / 回滚。
3. P2：重构更新助手运行方式后，再逐项收紧 Electron fuse；以升级兼容测试和实际二进制检查验证，不能只看配置。

本报告不阻断本次沿用既有未签名渠道的发行；该渠道的限制已经披露，未将本地检查称为签名、真机或生产端到端验证。
